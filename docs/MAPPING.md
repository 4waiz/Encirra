# Simulation ↔ 3D asset mapping

> Generated by `npm run layout` from `packages/shared/config/district.json`. Do not edit by hand —
> change the configuration and regenerate. Positions are plan coordinates in metres (x east, z towards the default camera).

## How the mapping works

- **Electrical buses → buildings.** Every building on the district platform is supplied by exactly one bus of the
  IEEE 33-bus benchmark (1-based bus numbers; pandapower index = number − 1). The layout generator assigns each building
  to the bus whose service point lies in the same block (or the nearest one). When a bus loses supply in the simulation,
  every building mapped to it goes dark in the 3D twin.
- **Facilities** are mapped explicitly (`facilities[].bus`, `facilities[].waterNode`).
- **Pumps → buses.** A pump motor is supplied by `water.pumps[].bus`; its electrical demand is computed from the hydraulic
  solution (P = ρ·g·Q·H / η) and added to that bus. If the bus is de-energized the pump stops and the hydraulic model is re-solved.
- **Cable routes** follow streets and are illustrative; impedances are the published Baran–Wu values.
